# 云配置评估 — 授权测试方法论

> **授权前提**：使用测试方提供的**只读**凭证或被动检查进行配置评估。本 skill 聚焦“错误配置暴露面识别”，禁止实际提权、横向移动、删改云资源或导出敏感数据；发现可提权路径时记录路径并走审批，不实际执行。

## 快速流程

1. 确认授权范围与所用凭证（优先只读审计角色）。
2. 梳理身份与权限、存储暴露、网络开放面、密钥/元数据暴露。
3. 识别错误配置与可能的提权/横向路径（只记录，不执行）。
4. 输出风险清单与修复建议。

## 评估维度

| 维度 | 检查点 |
|---|---|
| 身份/IAM | 过宽策略（`*:*`）、可被 assume 的角色、长期密钥、无 MFA、通配资源 |
| 存储 | 公开读写的对象存储桶、公开快照/镜像 |
| 网络 | 安全组/防火墙 0.0.0.0/0 开放敏感端口、公网暴露的管理面 |
| 密钥/元数据 | 代码/环境变量/实例元数据中的明文密钥（结合 `offensive-ssrf` 的最小化原则，仅验证可达） |
| 日志/监控 | 审计日志是否开启（供改进建议） |

## 提权/横向（只记录）

识别“权限枚举 → 可 assume 的高权角色 → 资源访问”等路径时，用只读 API 证明**路径存在**（如列出可假设角色），不实际 assume 并操作资源。

## 工具思路

优先使用云厂商原生只读审计 API / 配置快照；第三方审计工具以只读模式运行。所有操作限定授权账户。

## 修复建议

最小权限 IAM 与定期审阅；关闭公开存储、启用阻断公共访问；收敛安全组；密钥集中托管与轮换、禁用明文密钥；强制 MFA；启用审计日志。

## 边界与禁止

| 禁止 | 替代 |
|---|---|
| 实际 assume 高权角色并操作资源 | 只读证明可提权路径存在 |
| 删改/导出云资源与敏感数据 | 只读评估，记录证据 |
| 使用暴露的真实密钥 | 记录暴露与位置，建议吊销轮换 |
