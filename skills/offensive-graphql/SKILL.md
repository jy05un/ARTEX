# GraphQL — 授权测试方法论

> **授权前提**：仅在授权端点测试。禁止用深层嵌套/别名批量查询进行资源耗尽（DoS），仅以“证明缺少深度/复杂度限制”为止；越权测试用测试账号，不批量导出真实数据。

## 快速流程

1. 定位 GraphQL 端点（`/graphql`、`/api/graphql`、`/v1/graphql`）。
2. 尝试内省（introspection）获取 schema。
3. 梳理敏感 query/mutation 与对象关系。
4. 按授权矩阵用测试账号验证字段/对象级越权。
5. 评估查询复杂度限制与注入透传，最小化取证。

## 内省与 schema

```graphql
{ __schema { types { name fields { name } } } }
```

内省关闭时，用字段建议报错（did you mean）与常见命名猜测、客户端已知 query 还原 schema。

## 鉴权与越权

- 对象级：改 query 变量里的 id 访问他人（测试账号）对象，结合 `offensive-access-control`。
- 字段级：请求敏感字段（`email`、`token`、`role`）看是否按字段鉴权。
- mutation 越权：尝试调用高权限 mutation。

## 批量/嵌套（仅验证缺少限制）

- 别名批量：同一 mutation 用多别名一次发起（验证是否缺速率/批量限制，**少量**即可）。
- 嵌套深度：构造适度嵌套关系查询，证明“无深度/复杂度限制”，**不**做耗尽式深嵌套。

## 注入透传

GraphQL 变量最终进入后端数据层时可能透传 SQLi/NoSQL/命令注入——按对应 skill 的最小化原则验证。

## 修复建议

生产关闭内省；字段/对象级授权；查询深度与复杂度限制、别名/批量限制；持久化查询白名单；变量在后端安全处理。

## 边界与禁止

| 禁止 | 替代 |
|---|---|
| 深嵌套/海量别名做 DoS | 少量请求证明缺少限制 |
| 批量导出真实用户字段 | 测试账号证明越权 |
