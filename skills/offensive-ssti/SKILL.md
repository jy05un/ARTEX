# SSTI — 授权测试方法论

> **授权前提**：确认模板注入以“证明表达式被服务端求值”为止（如 `7*7` 回显 `49`）。禁止直接跳到 RCE 执行系统命令读写文件；若需证明可达 RCE，仅执行无害只读命令（如 `id`）并截断输出，破坏性利用走审批。

## 快速流程

1. 在所有回显用户输入的点插入数学探针，观察是否被求值。
2. 根据语法差异对模板引擎指纹。
3. 用引擎特定的只读表达式最小化确认影响。
4. 记录 PoC，给出沙箱/逻辑无关模板的修复建议。

## 探针与指纹

```
${7*7}   {{7*7}}   #{7*7}   <%= 7*7 %>   {7*7}
{{7*'7'}}         # Jinja2 → 7777777；Twig → 49
```

| 回显 | 可能引擎 |
|---|---|
| `49` + `{{7*'7'}}`=`49` | Twig / 其他 |
| `49` + `{{7*'7'}}`=`7777777` | Jinja2 (Python) |
| `${7*7}`=`49` | Freemarker / Thymeleaf / JSP EL |
| `#{7*7}` | Ruby ERB / 其他 |

## 分级确认（最小化）

确认求值后，只做足以证明风险等级的探测：

- 读取引擎内置对象/配置键（证明可读上下文）。
- 若评估沙箱逃逸可行，仅以无害只读命令（`id`/`whoami`）证明，截断输出，**不**读取敏感文件、不反弹 shell、不写文件。

## 修复建议

不要把用户输入拼入模板源；使用逻辑无关（logic-less）模板并以数据方式传参；引擎沙箱与白名单；对必须的动态模板做严格字符白名单。

## 边界与禁止

| 禁止 | 替代 |
|---|---|
| 反弹 shell / 写文件 / 读敏感文件 | 只读 `id` 截断输出证明 RCE 可达 |
| 直接上破坏性命令 | 先证明 `7*7` 求值，再分级 |
| 对无关进程/服务操作 | 限定在授权目标进程上下文 |
