# 命令注入 / RCE — 授权测试方法论

> **授权前提**：确认以“证明可注入并被执行”为止，仅执行**无害只读**命令（`id`、`whoami`、`hostname`）并截断输出，或用带外回连作为盲注判据。禁止反弹 shell、下载/执行外部载荷、读写敏感文件、建立持久化、横向移动——这些须走人在环路审批。

## 快速流程

1. 找出会被拼进系统命令/解释器的输入（文件名、ping/nslookup 功能、导出/转码、图像处理、ZIP/模板参数）。
2. 用命令分隔符与带外探针确认注入与执行。
3. 以无害只读命令最小化证明影响等级。
4. 记录可复现 PoC 与上下文，给出修复建议。

## 注入探针

```
; id          | id          `id`          $(id)
&& id         || id         %0a id
| nslookup 唯一子域.自有dns     # 盲注带外确认
```

- 回显型：直接观察 `uid=...` 输出。
- 盲注型：用 DNS/HTTP 带外回连唯一子域确认，或用可观测时延（`sleep 5`）。

## 常见载体

- OS 命令拼接（shell 调用）。
- 代码求值（`eval`/`exec`/反序列化联动，见 `offensive-deserialization`）。
- 模板注入升级（见 `offensive-ssti`）。
- 文件处理工具的参数注入（图像/压缩/转码库历史 CVE）。

## 分级取证

确认执行后仅取等级证据：当前用户（`id`）、主机名、是否 root/服务账号。**不**枚举全盘、不读凭证、不外带数据。足以写进报告即停。

## 修复建议

避免调用 shell，改用参数化 API/库函数；输入严格白名单（尤其文件名/路径）；最小权限运行；禁用危险求值函数；及时修补处理库 CVE。

## 边界与禁止

| 禁止 | 替代 |
|---|---|
| 反弹 shell / 交互式会话 | 单条无害只读命令截断输出 |
| 下载并执行外部二进制/脚本 | 仅带外回连确认出站 |
| 持久化、横向移动、读凭证 | 记录可达性，深入利用走审批 |
