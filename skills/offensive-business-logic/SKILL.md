# 业务逻辑缺陷 — 授权测试方法论

> **授权前提**：使用测试账号与测试商品/额度验证逻辑缺陷，**不**在生产环境产生真实下单、扣款、发货、退款等后果。确认缺陷以“证明流程可被绕过/状态可被非法转移”为止；涉及资金或不可逆动作的验证须走人在环路审批并尽量在测试环境进行。

## 快速流程

1. 梳理关键业务流程与状态机（下单→支付→发货、注册→验证→激活、申请→审批）。
2. 识别“前端约束/隐含假设”未在服务端强制的环节。
3. 用测试账号尝试跳步、重放、改值、并发。
4. 证明缺陷后停手并记录，不扩大真实影响。

## 常见模式

| 类别 | 探测 |
|---|---|
| 流程跳步 | 直接请求后续步骤端点，跳过校验/支付 |
| 状态篡改 | 篡改 `status`/`stage`/`approved` 字段 |
| 数值滥用 | 负数/超大数量、价格/折扣参数可控、四舍五入边界 |
| 优惠滥用 | 优惠券重复使用、叠加、引荐自刷 |
| 重放 | 重放一次性操作（领取、兑换、投票） |
| 条件竞争 | 并发请求突破“仅一次”限制（见下） |

## 条件竞争边界

对“限领一次/限兑一次/余额扣减”类操作，用少量并发请求验证是否存在 TOCTOU 窗口。仅发送足以证明的最小并发量，避免压测式请求；在测试账号/测试额度上验证。

## 数值与边界

负数量、超额、单位混淆、客户端计算价格被信任、整数溢出、货币精度。只用测试商品验证，不生成真实订单。

## 修复建议

服务端强制状态机与不变量校验；幂等键防重放；库存/额度扣减用原子操作或锁；金额/权限一律服务端计算与校验；审计关键操作。

## 边界与禁止

| 禁止 | 替代 |
|---|---|
| 生产真实下单/扣款/发货 | 测试账号 + 测试商品，证明即止 |
| 压测式高并发冲击 | 最小并发证明竞争窗口 |
| 领取/套取真实优惠或资金 | 证明机制缺陷，不实际获利 |
