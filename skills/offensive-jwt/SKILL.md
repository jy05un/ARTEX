# JWT — 授权测试方法论

> **授权前提**：用测试账号签发的令牌验证实现缺陷。若成功伪造/篡改令牌，仅用于**证明校验缺失**（如访问一个受保护的只读测试端点），禁止用伪造的高权限令牌对真实数据执行越权读写。

## 快速流程

1. 采集令牌，解码 header/payload（不验证签名也可读）。
2. 审查算法、声明、过期与签名校验。
3. 逐项验证已知实现缺陷（见下）。
4. 用测试端点证明可绕过，记录 PoC 与修复建议。

## 结构审查

解码三段（base64url）：`header.payload.signature`。关注 `alg`、`kid`、`jku`、`x5u`；payload 的 `exp`/`nbf`/`iat`/`aud`/`iss`/角色声明。

## 常见缺陷

| 缺陷 | 测试 |
|---|---|
| `alg:none` | 改 header 为 `{"alg":"none"}`、去掉签名，看是否接受 |
| RS→HS 混淆 | 用公钥当 HMAC 密钥以 HS256 重签（服务端误用验签密钥） |
| 弱 HMAC 密钥 | 对 HS256 离线字典爆破弱 `secret`（仅在授权下，用常见弱口令集） |
| `kid` 注入 | `kid` 路径穿越/SQL 注入指向可控密钥 |
| `jku`/`x5u` 可控 | 指向自有 JWKS（结合 SSRF 的最小化原则） |
| 声明未校验 | 篡改 `exp`（过期仍接受）、`aud`/`iss`、角色字段 |

## 影响证明（最小化）

篡改成功后，仅访问一个受保护的**只读测试端点**证明鉴权被绕过，不进行越权数据操作。

## 修复建议

服务端固定算法白名单（拒绝 `none`、不混用 RS/HS）；强随机密钥/密钥轮换；严格校验 `exp`/`aud`/`iss`；`kid`/`jku`/`x5u` 白名单或禁用；短有效期 + 服务端可吊销。

## 边界与禁止

| 禁止 | 替代 |
|---|---|
| 用伪造高权限令牌越权读写真实数据 | 只访问只读测试端点证明绕过 |
| 爆破生产主密钥用于长期访问 | 仅在授权下验证弱密钥可破，不留持久访问 |
