# SSRF — 授权测试方法论

> **授权前提**：确认 SSRF 以“能发起受控出站请求”为止。禁止用 SSRF 大规模扫描内网、拖取云元数据凭证后横向利用、或代理攻击第三方。云元数据（如 `169.254.169.254`）仅验证可达，不导出完整临时凭证并使用；取证截断敏感值。

## 快速流程

1. 找出会被服务端取用的 URL/主机/文件参数（webhook、图片抓取、PDF 渲染、导入、SSO 元数据、回调）。
2. 指向自有带外端点（Collaborator/自建 DNS+HTTP）确认服务端出站。
3. 探测内网可达性与云元数据端点（最小化）。
4. 评估协议走私与过滤绕过。
5. 记录 PoC，给出白名单/网络隔离修复建议。

## 识别与确认

- 任何接受 `http(s)://`、主机名、IP 的字段都是候选；也包括 `url=`、`image`、`callback`、`dest`、`feed`、XML 外部实体、Office/SVG 渲染。
- 盲 SSRF：无回显时用唯一子域名触发 DNS+HTTP 回连确认。

## 内网与元数据（最小化探测）

```
http://127.0.0.1:<port>/        # 本机服务探活
http://169.254.169.254/latest/meta-data/        # AWS IMDSv1（仅验证可达）
http://metadata.google.internal/computeMetadata/v1/   # GCP（需 Metadata-Flavor 头）
http://169.254.169.254/metadata/instance?api-version=...  # Azure
```

> 取证只截取“端点可达”证据（如响应前缀），**不**完整读取并使用临时凭证/token。

## 过滤绕过（验证可绕过性）

- IP 表示法：十进制 `2130706433`、八进制、`0x7f000001`、`[::1]`、`127.0.0.1.nip.io`。
- 重定向：指向自有 302 到内网地址。
- DNS 重绑定：TTL 为 0 的域名首次解析为公网、二次为内网。
- 协议走私：`gopher://`、`dict://`、`file://`（读本地文件时仅取非敏感证据）。

## 修复建议

出站地址白名单（按域名+解析后 IP 双重校验，防重绑定）；禁用非 http(s) 协议与跟随重定向；元数据服务强制 IMDSv2/隔离；网络层出站隔离。

## 边界与禁止

| 禁止 | 替代 |
|---|---|
| 用 SSRF 全端口/全网段扫描内网 | 仅验证少量关键端点可达 |
| 导出并使用云临时凭证横向移动 | 仅证明元数据端点可达，截断凭证值 |
| 经 SSRF 攻击无关第三方系统 | 回连限定在自有带外端点 |
