# 访问控制 / 越权 — 授权测试方法论

> **授权前提**：使用测试方提供的多组测试账号验证越权，**不**访问真实用户的个人数据。确认存在越权后只取最小证据（如“A 账号能读到 B 测试账号的对象 id/标题”），禁止批量遍历导出真实数据或执行越权的写/删操作。

## 快速流程

1. 用高权限测试账号登录，记录所有对象引用（id、uuid、文件名、订单号）与功能端点。
2. 换成低权限/另一测试账号或无会话，重放这些请求。
3. 判定水平越权（访问同级他人资源）、垂直越权（越级访问管理功能）、功能级授权缺失。
4. 取最小证据，记录可复现请求对。
5. 给出“服务端按会话主体校验每个对象归属”的修复建议。

## IDOR / 对象级越权

- 遍历/篡改对象标识：`?id=1001` → `1002`，UUID 替换为另一测试账号的 UUID。
- 关注非顺序但可枚举的引用（时间戳、base64 包装的 id、可预测 token）。
- 多步流程里中间步骤的对象引用常漏校验。

## 功能级 / 垂直越权

- 直接请求管理端点（`/admin/*`、`/api/internal/*`）而非依赖前端隐藏。
- 篡改角色相关字段：请求体里的 `role`、`is_admin`、`tenant_id`。
- HTTP 方法越权：GET 受限但 PUT/DELETE 未校验；`X-HTTP-Method-Override`。

## 多租户隔离

跨租户访问：替换 `tenant_id`/`org_id`，验证租户间数据是否隔离。只用两个测试租户验证，不触碰真实租户。

## 强制浏览

对已知命名规律的端点/文件做小范围探测（备份、导出、调试接口），仅验证可达与授权缺失，不下载大文件。

## 修复建议

每个请求在服务端按当前会话主体校验对象归属与权限；集中式授权中间件；不可枚举的对象引用（随机 UUID）仅作纵深防御而非唯一手段；管理功能服务端二次校验。

## 边界与禁止

| 禁止 | 替代 |
|---|---|
| 遍历导出真实用户数据 | 用 2 个测试账号证明可跨账号访问 |
| 执行越权的写/删操作 | 只读确认，必要的写验证走审批 |
| 用真实管理员账号验证垂直越权 | 用测试环境的低权账号尝试越级 |
